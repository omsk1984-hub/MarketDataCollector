### ❓ Почему 1–4 тика дошли до `ON CONFLICT` в БД?

**Ключевой механизм — эвикция из [`DeduplicationCache`](src/MarketDataCollector.Application/Services/DeduplicationCache.cs).**

- [`DeduplicationCache`](src/MarketDataCollector.Application/Services/DeduplicationCache.cs) — это **FIFO-кэш на 50 000 записей** (`DeduplicationCacheMaxSize = 50000` в [`MarketDataProcessorOptions`](src/MarketDataCollector.Core/Configuration/MarketDataProcessorOptions.cs:118)).
- Когда кэш заполнен, при каждой новой вставке эвиктируются **5 000 самых старых записей** (10% от `maxSize`), и только после этого добавляется новый ключ.
- За прогон через кэш проходят **1.7M тиков**, что вызывает **~340 циклов эвикции** (1.7M / 5 000). Кэш постоянно ротируется.

**Сценарий «тик проскочил кэш»:**

1. Тик `(BTC/USDT, binance, ts₁)` поступает в **батч N** → [`TryAdd`](src/MarketDataCollector.Application/Services/DeduplicationCache.cs:114) возвращает `true` (ключ уникален) → тик добавлен в кэш и уходит в БД.
2. После **~20 батчей** (20 × 2500 = 50 000 новых ключей) кэш переполняется. Самые старые записи, включая `ts₁`, **эвиктируются**.
3. Тот же тик `(BTC/USDT, binance, ts₁)` поступает повторно из WS (дубль доставки) в **батч N+M** (где M > 20) → `TryAdd` возвращает `true` (кэш уже забыл `ts₁`) → тик отправляется в БД.
4. **`ON CONFLICT DO NOTHING`** в БД находит уже существующую строку — вставка игнорируется, `inserted_count` не инкрементируется для этого тика.
5. Разница `batchSize - cachedCount - inserted` даёт `dedup_db` (см. [`MarketDataProcessor.cs:920`](src/MarketDataCollector.Application/Services/MarketDataProcessor.cs:920)).

**Почему dedup_db так мал (1–4 из 1.7M ≈ 0.0002–0.0005%)?** — потому что окно для этого сценария узкое:
- Большинство дубликатов WS приходят **в пределах 1–2 батчей** — кэш ещё помнит их ключи.
- Только единичные дубликаты запаздывают на десятки батчей и ловят «забывчивый» кэш.

**Вывод:** `dedup_db > 0` — **не ошибка, а ожидаемое поведение** при FIFO-кэше с фиксированной ёмкостью. Абсолютное значение (1–4 из 1.7M) пренебрежимо мало.
