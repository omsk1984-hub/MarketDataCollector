## 9. Ключевые проблемы и рекомендации

1. ⚠️ **Выбросы длительности записи батча (до 4,234 мс, повторные 3+ сек).** При batch_size=2500 среднее ~96 мс, но периодические 3–4 сек батчи затормаживают консьюмер и порождают стартовый backlog (~43K). **Действие:** проанализировать причины медленных INSERT (первый прогрев индексов, блокировки строк, план запроса), рассмотреть оптимизацию записи (batch batching/COPY, настройка индексов). Доступен `allocation_trace_20260804_120839.nettrace` для разбора.
2. ⚠️ **Lock contention +955 за прогон (~9.5/с).** Выше обоих прошлых прогонов. **Действие:** проверить блокировки в `DeduplicationCache` и вокруг записи батчей на `channel_index=0`; рассмотреть reduce-lock-contention (например, per-shard lock / lock-free структуры).
3. ⚠️ **Отсутствуют метрики дропов `ticks_dropped_count_total` / `ticks_dropped_silently_count_total` в CSV.** Дропы фиксируются только в логе (`real dropped: 0`). **Действие:** вернуть/экспортировать счётчики дропов канала для штатного мониторинга.
4. ⚠️ **Всплеск исключений в конце из-за обрыва WS при остановке** — не ошибка записи, но сигнализирует: recovery-loop при штатной остановке генерирует шум (исключения +80). Рассмотреть корректную отмену WS-подключений до остановки, чтобы исключить ложные исключения в конце прогона.
5. **Позитив для закрепления:** полный дренаж (backlog → 0), `received == incoming`, дропов 0, инвариант `received − processed == cache + db` точен (51,036 == 51,036), дедупликация целиком на кэше, LOH ~17 MB, GC-паузы ~107 мс, WS-распределение равномерное. Прогон пригоден как **базовый (baseline)** для сравнения последующих сборов.
