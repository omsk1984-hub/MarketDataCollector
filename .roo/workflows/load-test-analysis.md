# Workflow: Нагрузочное тестирование и анализ

Твоя задача — провести нагрузочное тестирование по строгому алгоритму. 
**НИКОГДА не запускай команды в foreground** — все долгоживущие процессы запускаются в background.

## Переменные (уточни у пользователя, если не указаны)
- `SERVER_CMD` — команда запуска сервера (например, `npm run start:server`)
- `CONSUMER_CMD` — команда запуска консьюмера (например, `npm run start:consumer`)
- `COUNTER_CMD` — команда запуска счетчика (например, `python counter.py`)
- `TEST_DURATION` — длительность теста в секундах (по умолчанию 60)
- `LOGS_DIR` — путь к папке логов (по умолчанию `./load-test/logs`)
- `PIDS_DIR` — путь к папке PID-файлов (по умолчанию `./load-test/pids`)

---

## Шаг 1: Подготовка окружения

1. Создай папки `{{LOGS_DIR}}` и `{{PIDS_DIR}}` (если их нет) через `mkdir -p`.
2. Очисти старые логи: `rm -f {{LOGS_DIR}}/*.log {{PIDS_DIR}}/*.pid`.
3. Проверь, что команды из переменных существуют (прочитай `package.json` или `pyproject.toml`).
4. **Если чего-то не хватает — СТОП, спроси пользователя.**

---

## Шаг 2: Запуск сервера

Выполни команду строго в таком виде (background + tee + PID):

После запуска:
1. Подожди 3 секунды (`sleep 3`).
2. Проверь, что процесс жив: `kill -0 $(cat {{PIDS_DIR}}/server.pid)`.
3. Если процесс умер — прочитай `server.log`, найди ошибку, **СТОП и сообщи пользователю**.
4. Если жив — проверь, что порт слушается (например, `curl -s http://localhost:<PORT>/health`).
